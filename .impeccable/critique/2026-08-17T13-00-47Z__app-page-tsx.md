## Design Specificity Verdict

The Coach's Call Sheet system is strongly authored for Any Given Pick: field green, warm paper, condensed command typography, maize commitments, clay deadlines, ruled matchups, and route geometry form a coherent product language without resembling a sportsbook.

The independent design review identified information architecture—not visual identity—as the weak point. The deterministic scan reported 138 advisory quality findings: 126 font-size token/documentation findings and 12 color findings, primarily in `app/globals.css`. These findings are mostly design-token drift and do not explain missing games or features. The CLI emitted exit code 2 because advisory metadata was inconsistent; several values are intentional component-level tokens. No reliable browser overlay was possible because mutable script injection was unavailable; screenshots, DOM geometry, console evidence, live API checks, and production database reads were used instead.

## Overall Impression

The mobile PWA is visually credible and the core pick interaction is robust. The largest opportunity is to make the weekly state machine obvious: what week is current, whether it is published, when odds and scores were actually fetched, and where the user goes after lock. Today those distinctions live in backend status fields and scattered routes, so correct behavior looks like missing content.

## What's Working

1. Pick controls are highly legible and accessible: large two-team choices, redundant selected states, semantic controls, review-before-submit, and clear completion checks.
2. Deadline and draft integrity are unusually strong: server checks, local recovery, debounced sync, offline messaging, eligibility rechecks, and timestamped receipts reduce submission anxiety.
3. The production schedule import itself is complete. Preseason Week 2 contains all 16 games and all 32 teams with zero import errors or warnings.

## Priority Issues

### [P1] Preseason Week 2 exists but is not published

**Why it matters:** Players see only Preseason Week 1 because `getCurrentPlayerWeek` hard-filters to `status = published`. Week 2 has all 16 games and a future deadline, but remains a draft. This is the direct cause of the missing current games.

**Fix:** Publish Preseason Week 2 after the admin review. Add a visible “player-facing week” status in Admin and Home so the active slate cannot be confused with the newest imported draft.

**Suggested command:** `$impeccable harden`

### [P1] Available odds cannot preload while a week is a draft

**Why it matters:** ESPN currently supplies moneylines for all 16 Week 2 games, but the database has no odds. Score/odds sync excludes draft weeks, and publishing does not trigger an immediate refresh. Players can therefore open a newly published slate without the promised reference lines.

**Fix:** Allow odds-only synchronization for future draft weeks or trigger `runEspnScoreSyncWithHealth` immediately after publishing. Preserve the rule that only moneylines show for every game and O/U shows only for the designated Monday game.

**Suggested command:** `$impeccable harden`

### [P1] “Every minute” checks do not fetch provider scores

**Why it matters:** Activity and Results poll `/api/activity/scores` every minute, but that endpoint only reads stored health. The provider job is daily; Checkly can recover stale syncs during game windows, yielding roughly a 40-minute freshness target—not one-minute results. Finished games may appear missing or pending long after final whistle.

**Fix:** Introduce a secure, throttled live-score sync during active game windows, then refresh the UI. Update copy to state the real cadence until that exists. Make health report checked weeks/games so `healthy with 0 games checked` is not mistaken for complete data.

**Suggested command:** `$impeccable clarify` then `$impeccable harden`

### [P1] Results is functionally present but missing from mobile navigation

**Why it matters:** Mobile exposes Home, Picks, Standings, Activity, and Profile; `/results` is omitted and identifies itself as Standings. Users reasonably conclude Results is missing. Activity also keeps final Week 1 as “Current” until Week 2 is published, making the archive look incomplete.

**Fix:** Use four primary mobile destinations: Home, Picks, Results, Profile. Turn Results into a post-lock hub with Standings, Weekly Cards, and Mine. Keep Activity as the “Mine” deep link or tab.

**Suggested command:** `$impeccable distill`

### [P1] Publishing lacks completeness and chronology safeguards

**Why it matters:** Any nonzero slate with one tiebreaker can publish. Multiple weeks can remain published, and the selected current week is based on phase/week-number sorting rather than kickoff chronology. An accidental future regular-week publish could replace the real slate.

**Fix:** Validate expected provider game count/team uniqueness, allow only one player-facing published week, finalize or lock the outgoing week during transition, and select current week by explicit active status/chronology.

**Suggested command:** `$impeccable harden`

### [P2] Mobile feature discoverability and orientation need consolidation

**Why it matters:** Email reminders are hidden in a collapsed Profile section; profile photos never appear in Results or Standings despite promising recognition; the long picks list loses progress and deadline context; expired location can still say “Cleared.”

**Fix:** Add a compact sticky progress/review strip, day-group the slate, link reminder settings from Home and receipts, display privacy-safe avatars socially or revise the promise, and make all eligibility labels use freshness-aware state.

**Suggested command:** `$impeccable adapt`

## Persona Red Flags

**Casey, distracted mobile player:** After several picks, progress and lock time are off-screen and the review action is below the entire slate. Returning after an interruption requires rescanning all games.

**Jordan, first-timer:** Activity, Results, and Standings do not explain private history versus public cards versus rank. Results has no mobile nav item, while ML/O/U and TB diff assume football-odds fluency.

**Riley, commissioner/stress tester:** A complete imported slate can remain invisible because it is still a draft; an incomplete slate can still pass publish validation; a future published week can supersede the real one; a “healthy” sync can report zero checked games.

## Questions to Consider

- Should publishing the next week be a single transition that closes the previous slate, preloads odds, and sends reminders?
- Are Standings, Weekly Results, and My Activity separate destinations, or three views of one post-lock Results hub?
- Should a health check be green when zero games were checked and a complete future slate has no odds?
- If a player returns with three picks missing, why make them hunt for those three?
